# Сумиби — сайт ресторана с доставкой

Next.js 16 (App Router) · TypeScript · Tailwind CSS 4. Подробный README с базой, оплатой и выкладкой — на этапе 8.

## Быстрый старт

```bash
npm install                  # заодно сгенерирует Prisma Client (postinstall)
cp .env.example .env         # DATABASE_URL и прочие переменные
docker compose up -d         # PostgreSQL 16 на localhost:5432
npm run db:migrate           # применить миграции
npm run db:seed              # демо-меню, зоны, промокоды, отзывы, настройки; сотрудники owner и manager
npm run dev                  # http://localhost:3000, витрина компонентов — /styleguide, админка — /admin
```

Полный сброс базы с демо-данными: `npm run db:reset`. Повторный `db:seed` безопасен: записи обновляются по slug,
настройки, изменённые в админке, не затираются.

## Админ-панель (`/admin`)

Светлая, рассчитана на планшет (работает и на телефоне). Вход по логину и паролю.

- **Сотрудники.** Первый запуск `db:seed` создаёт `owner` (владелец) и `manager` (менеджер) с паролями из
  `ADMIN_OWNER_PASSWORD` / `ADMIN_MANAGER_PASSWORD`; если переменные пустые, сид сгенерирует пароли и напечатает их один раз.
  Дальше владелец добавляет сотрудников, меняет роли и пароли в разделе «Сотрудники». Из консоли (например, если
  забыт пароль владельца): `ADMIN_PASSWORD='…' npm run admin:create -- login "Имя" OWNER`.
- **Роли.** Владелец — всё. Менеджер — заказы, меню и брони; остальные разделы ему не показываются, а сервер отклоняет
  запросы к ним (права проверяются в каждом действии, не только в меню).
- **Безопасность входа.** Пароли хранятся как scrypt-хэш с солью; сессия — случайный токен в httpOnly-cookie, в базе лежит
  только его хэш; вход ограничен по частоте (по IP и по логину).
- **Заказы:** лента обновляется сама каждые 5 секунд, новый заказ подсвечивается и звучит сигнал (кнопка «Включить звук» —
  браузеры не дают играть звук без нажатия). Статус меняется в одно касание, отмена — с обязательной причиной,
  «Печать для кухни» — чек шириной 80 мм.
- **Предзаказы:** о заказе ко времени ресторан узнаёт за N минут до времени (по умолчанию 120, «Настройки»): сигнал в ленте
  и сообщение в Telegram. Все будущие предзаказы на любые даты — вкладка «Предзаказы». Пока лента открыта, напоминания
  уходят сами; страховка на сервере — cron раз в 5 минут:
  `*/5 * * * * curl -fsS -X POST -H "Authorization: Bearer $CRON_SECRET" https://<домен>/api/cron/preorder-reminders`.
- **Меню:** блюда (создать, копировать, удалить, стоп-лист одним переключателем, порядок перетаскиванием),
  категории, группы добавок. Фото кадрируется 4:3 в браузере, сервер сжимает его в WebP 1600×1200 и убирает метаданные.
  Изменения видны на сайте сразу (сбрасывается кэш меню).
- **Доставка:** зоны рисуются на схеме кликами по точкам (координаты можно вставить и списком), стоимость, минимальная
  сумма, порог бесплатной доставки, время; часы приёма заказов и пауза приёма. С ключом `YANDEX_MAPS_JS_API_KEY`
  зоны показываются и на Яндекс Карте (каркас `src/components/maps/YandexMap.tsx`, админка и страница «Доставка»).
- **Маркетинг:** промокоды, акции (блок «Акции» на главной) и баннеры (полоса над хитами и над меню).
- **Брони и отзывы:** смена статуса брони, публикация отзывов на главной.
- **Аналитика:** выручка, число заказов, средний чек и популярные блюда за сегодня, 7 и 30 дней. Отменённые и
  неоплаченные онлайн-заказы не учитываются. Выгрузка в CSV (заказы, выручка, блюда) открывается в Excel и Google Таблицах;
  имён, телефонов и адресов гостей в ней нет.
- **Журнал** (только владелец): кто, когда и что сделал — входы, статусы заказов, цены и стоп-лист, зоны, акции,
  сотрудники, выгрузки. Фильтры по разделу и сотруднику.
- **Настройки:** название, адрес и координаты, телефоны и мессенджеры, часы зала, тексты плашки, бонусы, заказ ко времени.
  Шапка, подвал и главная берут эти данные из базы.

Фото блюд: `STORAGE_DRIVER=local` — файлы в `UPLOAD_DIR` (по умолчанию `./uploads`, отдаются по адресу `/uploads/…`;
на сервере сделайте эту папку постоянной), `STORAGE_DRIVER=s3` — S3-совместимое хранилище (Yandex Object Storage и др.),
ссылки строятся от `S3_PUBLIC_URL`.

## Гость: кабинет, бонусы, бронь, контакты, отзывы

- **Вход по номеру и коду** (`/account`), без пароля. Код — 4 цифры, живёт 5 минут, 5 попыток; в базе хранится только HMAC
  кода. Лимиты: новый код раз в минуту, 5 кодов в час на номер, 20 — на IP. Сессия — httpOnly-cookie на 90 дней.
- **SMS — каркас.** Интерфейс `SmsProvider` в `src/server/sms/index.ts`; сейчас только демо-режим (`SMS_PROVIDER=demo`):
  SMS не уходит, код показывается на экране. В продакшене демо-режим выключен (вход недоступен), пока не задан
  `ALLOW_DEMO_SMS=true` или не подключён настоящий сервис.
- **Корзина** хранится в браузере и после входа привязывается к аккаунту (`Cart`): на другом устройстве та же корзина.
- **Кабинет:** история заказов с кнопкой «Повторить» (блюда по сегодняшним ценам; закончившиеся пропускаются),
  бонусы и их история, сохранённые адреса (запоминаются после заказа с доставкой), профиль (имя, почта для чеков).
- **Бонусы:** начисляются вошедшему гостю за оплаченный онлайн или выполненный заказ (процент — «Настройки»),
  списываются при оформлении до заданного процента стоимости блюд. Списание атомарное (баланс не уходит в минус),
  при отмене заказа списанные бонусы возвращаются, начисленные — снимаются.
- **Бронь** (`/booking`): день на 14 дней вперёд, время с шагом 30 минут по часам зала (не раньше чем через час,
  последняя посадка — за час до закрытия), гости до 12. Ресторан получает уведомление; брони — в админке.
- **Контакты** (`/contacts`): адрес, карта, часы, телефон, мессенджеры, форма обратной связи. Сообщения — в админке
  («Отзывы» → «Сообщения с сайта») и уведомлением в Telegram.
- **Отзывы:** гость оставляет отзыв на странице выполненного заказа (ссылка есть в кабинете); публикует их владелец.
- **Документы:** `/privacy` и `/offer` — шаблоны с подстановкой реквизитов из настроек. **Их должен проверить юрист.**

## Оформление заказа и доставка

- Суммы, скидки и доставку считает сервер (`src/lib/order/calc.ts`) по ценам из базы. Браузер присылает только id блюд,
  добавок и количество.
- Адрес: подсказки и координаты через сменный модуль (`src/server/geo`): Яндекс (Геосаджест + Геокодер), DaData или
  демо-справочник без ключей (`GEO_PROVIDER=mock`). Сервер подписывает найденную точку (`APP_SECRET`), поэтому подменить
  координаты при оформлении нельзя.
- Зоны доставки — многоугольники в таблице `DeliveryZone`. При пересечении действует зона с меньшим `sortOrder`.
- Время: часы приёма заказов и слоты «ко времени» в часовом поясе ресторана (`Settings.timezone`).
- Демо-промокоды: `ОГОНЬ10` (10 %), `WELCOME300` (300 ₽ от 1 500 ₽).
- Уведомления о заказах: Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), иначе запись в лог. В сообщения не попадают
  персональные данные гостя.

## Оплата

- Модуль `PaymentProvider` (`src/server/payments`): тестовая заглушка `mock` и ЮKassa (`yookassa`), выбор — `PAYMENT_PROVIDER`.
- Данные карт сайт не принимает и не хранит: гость оплачивает на странице платёжного сервиса.
- Заказ с онлайн-оплатой создаётся в статусе «Ждём оплату». Оплаченным он становится **только** по уведомлению сервиса
  (`POST /api/payments/webhook/<provider>`). Подлинность: ЮKassa — IP из официального списка + статус платежа всегда
  перепроверяется запросом к API; заглушка — подпись HMAC.
- Повторные уведомления безопасны: событие записывается в `PaymentEvent` с уникальным ключом, заказ блокируется на время
  обработки, бонусы начисляются одной записью (`BonusTransaction` с уникальной парой заказ+тип), сумма платежа сверяется с заказом.
- Подключение ЮKassa: задайте `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`; в личном кабинете
  укажите URL уведомлений `https://<домен>/api/payments/webhook/yookassa` и события `payment.succeeded`, `payment.canceled`.
  Обратный прокси (Caddy/Nginx) должен перезаписывать `X-Forwarded-For` реальным IP клиента.
- Чеки 54-ФЗ — через «Чеки от ЮKassa»: `YOOKASSA_RECEIPTS=true` и `YOOKASSA_VAT_CODE` (+ при необходимости
  `YOOKASSA_TAX_SYSTEM_CODE`, признаки предмета и способа расчёта). С платежом уходят позиции заказа; скидка и бонусы
  распределяются по блюдам так, чтобы сумма чека совпала с платежом, доставка — отдельной позицией. Гость указывает почту
  для чека (обязательно для «Чеков от ЮKassa»). Значения налоговых параметров выбирает бухгалтер.
- Страница заказа `/order/<токен>` обновляется сама (опрос раз в 5 секунд), при неудачной оплате предлагает повторить.

## Проверки

```bash
npm run lint         # ESLint + проверка, что цвета и размеры шрифтов идут только из токенов
npm run typecheck    # TypeScript, строгий режим
npm test             # Vitest: суммы, скидки, зоны, слоты, корзина, телефон, токены и контраст WCAG
npm run test:integration  # Vitest с настоящей базой: идемпотентность уведомлений об оплате и бонусов
npm run build
npx playwright install chromium   # один раз
npm run test:e2e     # Playwright на 375 и 1440 px (сам запустит npm start с RATE_LIMIT_SCALE=50; нужна база с сидом
                     # и пароли ADMIN_OWNER_PASSWORD / ADMIN_MANAGER_PASSWORD в .env — те же, что при сиде)
```

## Где что лежит

- `prisma/schema.prisma` — модель данных; `prisma/seed-data/menu.ts` — демо-меню.
- `src/server/menu.ts` — чтение меню из базы с кэшем (тег `menu`, сбрасывается из админки).
- `src/config/restaurant.ts` — демо-данные ресторана (вымышленные, помечены TODO): из них сид заполняет настройки,
  дальше всё правится в админке. Из файла напрямую берутся только название для логотипа и SEO-заголовки.
- `src/server/site-info.ts` — контакты и тексты для шапки, подвала и главной из настроек.
- `src/app/admin`, `src/server/admin`, `src/components/admin` — админ-панель; `src/proxy.ts` — не пускает в `/admin` без входа.
- `src/app/globals.css` — дизайн-токены «Тушь и огонь». Единственное место с «сырыми» цветами и размерами.
- `src/design/tokens.ts` — зеркало цветов для TS (тест сверяет его с CSS).
- `src/components/ui` — кнопки, поля, метки; `src/components/site` — шапка, подвал, карточка блюда; `src/components/brand` — печать, мазок кисти, иероглифы.
